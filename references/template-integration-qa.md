# 模板接入与原生数据验收经验

新模板准备、runtime 新组件发布、配色适配或兼容性排查时读取。这里是开发/发布阶段的验证方法，不把每一次普通内容填充变成全套人工验收。

## 准备和发布

- 保留用户原始 PPTX；标记、拆槽位、调整 Group 和主题化都在准备副本中完成。记录源文件 SHA-256、准备脚本/修改范围、编译产物和 runtime 版本。
- 已发布模板版本不可原位覆盖；修订发布新版本，旧版禁用新选择但保留历史任务引用。编译前确认 lint 通过，模板变动后重建 Manifest/schema/lock；旧文件验收不能自动作为新文件的证明。
- 集成现有产品风格时，使用现有设计目录与解析器；自动预选匹配模板，同时保留用户手动更换。后台也校验选择，避免前后端默认不一致；不要仅为模板另建一套风格/配色选择器。
- 有效设计由应用解析器决定，不直接用一条数据库绑定推断最终配色；用户、文章、设计修订变化时刷新，任务提交时冻结实际解析结果。

## 目录和文本的视觉边界

章节计划来自所有目录容量的并集，而非第一张目录的固定项数。若用户已授权适配模板，可以将目录制作为 `@1@1[3-5]` 等变长列表：预制到上限，后续 Group 对应 `@1@2` 到 `@1@5`，容量仍与默认章节范围求交。禁止仅为旧四项目录强行丢弃第五章。

跟随 Item 的分隔线、装饰、背景和序号都应在相应 Group 内。只移动文本、不移动分隔线，会在缩到三项时留下错位线条。原本固定于页面的装饰不应盲目移入列表。

文本长度合法不代表视觉无溢出。源标题可能靠手动换行避开图片，但文本框实际横跨图片区域，替换成连续文字后就会重叠。检查真实形状边界与代表性最长中英文；必要时在准备副本拆成承担明确行意图的短标题槽位，分别定义长度。不要机械截尾、任意全局缩字或让文本框自动增长掩盖错误。

## 分层验证

1. **先直接调用 runtime**：compile → 内容校验 → 确定性绑定 → 最终校验 → generate → verify。新表格/图表无需每次通过慢速产品生成链路调试。
2. **数据边界**：表格最小/最大行、空模板单元格、XML 特殊字符；图表最小/最大分类、固定系列数、非法数值、缺失/外部工作簿；重复使用同一图表模板至少两次并填入不同数据，证明互不覆盖。
3. **结构对账**：盘点所有标记节点与 Manifest 数据合同；对比图表缓存、公式和 XLSX 数值/范围。`verify` 的包检查不能替代数据对账。
4. **模板视觉回归**：覆盖最密集列表、最短列表、连续长标题、表格行高和至少一组对比明显的配色。确认反色文字、图表系列、手绘图例同步。渲染缺字时先检查 CJK 字体与 fontconfig，不立即判定 PPTX 损坏。
5. **原生验收**：新组件或修改过的模板，用最终精确文件在 Microsoft PowerPoint 打开并检查是否出现修复提示；检查编辑数据能打开 Excel 且数值一致，必要时导出 PDF 检查排版。普通批量填充仍遵循默认程序 gate，无需每份重复这一开发验收。
6. **最后产品流程**：接入产品时，用最终已发布版本，从一篇有代表性文章走完整流程，核对预选、手动更换、配色、章节、生成状态和下载文件。记录模板版本、任务引用和实际最终文件哈希。

最终报告分别标明单测、runtime 生成、包检查、视觉、PowerPoint/Excel、产品流程哪些已完成。截图只证明对应文件当时状态；二进制修改后应重做受影响检查。可编辑图表需要工作簿证据，不能用截图替代。

## 开发环境排查

- 磁盘代码/新构建成功不能证明服务正在运行新版本。检查本次任务对应的 API、worker、runtime 进程和端口；启动脚本退出不一定终止子进程，旧 worker 可能抢占任务。
- 只停止自己确认归属且允许停止的开发进程，先查进行中的任务。记录关联 ID、模板版本、阶段耗时与错误，不能吞错或把基础设施故障当作内容失败。
- 付费端到端生成遵循当前用户授权，不把某次允许计费的授权固化进 Skill。先用直接 runtime 缩短迭代，最终产品验收按用户的质量要求执行。
